## Enrichment project: Style guide

***Reminder:** Enrichment projects are fully customizable with no specific requirements. These instructions are a guide if you’re not sure where to start. You can follow them closely or deviate as much as you like! You can even create enrichment projects from scratch.*

## Description

In this enrichment project, you will create and document your own R style guide and practice following it. 

## Instructions

1. **Create style guide documentation.** Refer to the tidyverse style guide, Dr. Dowling's style guide, and other examples online to determine what belongs in a style guide and how to document it.
2. **Demonstrate the style guide in practice.** Create a document (such as an R notebook or Quarto file) that demonstrates each feature of your style guide. Use comments liberally to highlight where you're applying each feature.
3. **Explain your reasoning.** Include explanation or reflection about the choices you made and why.

Your style guide may be modeled after existing guides but should have notable differences. If you think an existing style guide is already perfect, approach this as creating a reasonable alternative.

### Challenge suggestions

1. Apply your style guide across multiple documents or a full project repo
2. Combine this with another project (either a second enrichment project or a core skills project you’ve submitted), applying your documented style to all elements
3. Expand beyond typical style guide territory. Add standards for ggplot themes, YAML header organization, commit message structure, etc.
4. Create two contrasting style guides (one well-designed, one poorly constructed) with thoughtful comparison explaining what makes the latter functionally problematic
5. Configure the [`styler` package](https://styler.r-lib.org/) to implement your style.

## Submission

Detailed submission instructions are included in the `enrichment-submission.qmd` document and the [GitHub Submissions Guidelines](http://d2m-r.github.io/assessment/misc/gh-submissions.html). 

Reminders:

1. Copy the `-enrichment-submission.qmd` doc from `student-hub/templates` into the top level of your repo and complete in full. 
2. Ensure you create a *private* repo. Invite all instructors as collaborators with Write+ permissions.
3. Initiate a `feedback` branch and pull request.
4. Your work is not submitted until you have completed the [Submission Form](http://d2m-r.github.io/submit.html).

If your enrichment project includes components that cannot reasonably be submitted as part of a GitHub repository (for example, large data files, interactive web apps), please confirm with Dr. Dowling about how to submit those components.

Even if some or most of your project is submitted outside of GitHub, you should still use a GitHub repository to manage your code and other files as much as possible.
