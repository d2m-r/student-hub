## Enrichment project: Community Contribution

***Reminder:** Enrichment projects are fully customizable with no specific requirements. These instructions are a guide if you’re not sure where to start. You can follow them closely or deviate as much as you like! You can even create enrichment projects from scratch.*

## Description

This “project” isn’t much of a project, it just is what it is.

Contribute knowledge or help to a crowd-sourcing support page, like stack overflow or an R-focused subreddit.

Show that you’ve done so with screenshots, then include in your submission doc:

1. A summary of the question(s) you responded to and the response(s) you gave
2. Some kind of reflection
3. Specific explanations of your contributions and their relationship to the course

## Submission

Detailed submission instructions are included in the `enrichment-submission.md` document and the [GitHub Submissions Guidelines](http://d2m-r.github.io/assessment/misc/gh-submissions.html). 

Reminders:

1. Copy the `enrichment-submission.qmd` doc from `student-hub/templates` into the top level of your repo and complete in full. 
2. Ensure you create a *private* repo. Invite all instructors as collaborators with Write+ permissions.
3. Initiate a `feedback` branch and pull request.
4. Your work is not submitted until you have completed the [Submission Form](http://d2m-r.github.io/submit.html).

If your enrichment project includes components that cannot reasonably be submitted as part of a GitHub repository (for example, large data files, interactive web apps), please confirm with Dr. Dowling about how to submit those components.

Even if some or most of your project is submitted outside of GitHub, you should still use a GitHub repository to manage your code and other files as much as possible.
